# Ćwiczenie 14: testy E2E w Playwright (40 min) [dla chętnych]

Branch `dodatki-ssr-e2e`. Opis techniczny: [docs/E2E.md](../docs/E2E.md).

## Kroki
1. `npx playwright install chromium`, potem `npm run e2e`. Wszystko zielone na obu aplikacjach. Zapisz liczby z linii "żądania przy wejściu na listę".
2. `npm run e2e:ui`. Kliknij test "krytyczne wymaga osoby i terminu" i przejdź po osi czasu krok po kroku.
3. Napisz nowy test w `e2e/statystyki.spec.ts`: wejście na "Statystyki" z menu pokazuje kafelek "Po terminie" z liczbą 10. Użyj `getByRole('link', { name: 'Statystyki' })` i `getByText`.
4. Napisz test: dodanie komentarza w szczegółach #3 pokazuje go na liście i toast "Dodano komentarz".
5. Uruchom testy legacy po swoich zmianach z ćwiczeń: `npm run e2e -- --project=legacy`. Czy migracja coś zepsuła?
6. Zepsuj celowo aplikację (np. usuń `track` albo zmień tekst przycisku "Zapisz") i zobacz, który test to łapie i jak wygląda raport (`npx playwright show-report`).

## Kryteria ukończenia
- [ ] 2 nowe testy przechodzą na `legacy` i `modern`.
- [ ] Żaden test nie używa `waitForTimeout` ani selektorów po klasach CSS (poza tabelą `tbody tr`).

## Dla chętnych
- Test "zepsutego serwera" dla listy przez `page.route('**/api/tickets*', r => r.fulfill({ status: 500 }))` na branchu `main` (bez SSR). Dlaczego na tym branchu z SSR to nie zadziała przy `page.goto`?
- Przeczytaj `e2e/przyklady/sso.setup.example.ts` i dopasuj do SSO w swoim projekcie.
